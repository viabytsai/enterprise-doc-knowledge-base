# 企业内部知识库智能问答助手 PRD

| 项目 | 内容 |
| --- | --- |
| 文档版本 | v1.0 |
| 产品状态 | MVP 需求定义 |
| 目标平台 | Web 本地部署 |

## 1. 产品概述

### 1.1 产品定位

企业内部知识库智能问答助手是一款面向制度、流程、研发规范与产品手册的本地 Agentic RAG（基于 Agent 工具编排的检索增强生成）应用。用户上传或导入企业文档后，可通过自然语言提问获得基于原始资料的回答，并查看文档名称、页码和原文片段等引用依据。

产品不以通用聊天为目标。它解决的是企业资料分散、关键词检索效率低、制度答案难以核验的问题，并在资料不足时明确拒答，以降低大模型幻觉风险。

### 1.2 典型场景

- 员工查询差旅、报销、请假、远程办公等制度。
- 研发人员查询发布规范、故障处理流程、接口说明。
- 产品或运营人员查询产品配置、权限规则、版本差异。
- 管理员验证文档是否已解析、召回结果是否正确、重排序是否有效。

### 1.3 示例问题

- 出差住宿标准是多少？
- 试用期员工可以申请年假吗？
- 发布生产环境前需要完成哪些检查？
- v1 和 v2 产品手册中权限配置有什么差异？
- 当前资料是否说明了远程办公政策？

## 2. 目标与边界

### 2.1 产品目标

1. 支持本地企业文档导入、解析、向量化和索引管理。
2. 基于检索到的资料回答问题，并在回答中提供可点击或可展开的引用来源。
3. 通过“向量召回 + 重排序”提高复杂问题下的上下文相关性。
4. 提供检索调试和离线评估能力，量化优化效果。
5. 完成一个可演示、可部署、可在简历中说明技术决策的 RAG 项目闭环。

### 2.2 非目标

- MVP 不处理扫描版 PDF 的 OCR、图片问答和表格结构化理解。
- MVP 不接入企业 SSO、组织权限体系或在线协作文档。
- MVP 不构建复杂多 Agent 编排；仅保留可扩展的任务路由接口。
- MVP 不承诺替代正式制度审批或人事、财务系统。

## 3. 用户与权限

| 角色 | 主要诉求 | 权限 |
| --- | --- | --- |
| 普通用户 | 快速获得有依据的答案 | 浏览已发布知识库、提问、查看引用和历史会话 |
| 知识库管理员 | 维护资料与检索效果 | 上传、删除、重建索引、查看解析状态和检索调试 |
| 演示者/开发者 | 展示系统可靠性 | 维护评估集、运行评估、查看指标对比 |

MVP 可以先使用单一管理员账号或开发模式，不实现完整认证；API 层需预留用户与知识库标识字段，避免后续数据模型重构。

## 4. 核心用户流程

### 4.1 文档入库

1. 管理员进入“知识库管理”页面，上传 PDF、DOCX、Markdown 或 TXT 文件。
2. 系统校验文件类型、大小与重复文件；为文件创建解析任务。
3. 解析服务提取正文、标题层级、页码与文件元数据。
4. 系统按标题和段落进行语义分块，生成文档块及其元数据。
5. 使用嵌入模型将文档块写入向量库；完成后展示“已就绪”状态和分块数量。

### 4.2 智能问答

1. 用户在问答页面输入问题。
2. LangGraph Agent 判断任务类型，并决定是否调用知识库工具。
3. Agent 调用 `search_knowledge`，系统将问题向量化，在已就绪文档块中召回 Top 20 候选片段。
4. 重排序模型对“问题 - 候选片段”逐对打分，选取相关上下文；Agent 可继续调用 `get_source` 等工具核实内容。
5. 系统调用大语言模型 API，要求其仅依据工具结果回答，并为关键结论标记引用。
6. 前端流式展示答案、引用来源、Agent 工具轨迹、耗时和无依据提示。

### 4.3 质量评估

1. 开发者维护包含标准来源的评估问题集。
2. 系统分别以“仅向量检索”和“向量召回 + 重排序”运行评估。
3. 系统输出 Recall@5、引用命中率、平均响应时长和失败样例。
4. 开发者据此调整分块策略、召回数量和上下文数量，并再次验证。

## 6. RAG 技术方案

### 6.1 模型选型

| 模块 | 选型 | 说明 |
| --- | --- | --- |
| 大语言模型 | 可配置的 LLM API | 负责基于上下文生成回答；兼容 OpenAI 风格接口，便于替换供应商 |
| 嵌入模型 | `BAAI/bge-small-zh-v1.5` | 约 24M 参数，输出 512 维向量，适合轻量中文语义检索 |
| 重排序模型 | `BAAI/bge-reranker-v2-m3` | 约 568M 参数，对问题与候选片段打分，提升最终上下文精度 |
| 向量数据库 | Chroma | 支持本地持久化与 metadata 过滤，便于 MVP 部署 |

### 6.2 索引流程

```text
文件上传
  -> 文档解析（正文、标题、页码）
  -> 清洗与按标题/段落分块
  -> 写入 chunk metadata
  -> bge-small-zh-v1.5 生成 512 维向量
  -> Chroma 持久化索引
```

文档块 metadata 至少包含：`document_id`、`file_name`、`file_type`、`page_number`、`section_title`、`chunk_index`、`created_at` 和 `content_hash`。

### 6.3 查询流程

```text
用户问题
  -> 问题向量化
  -> Chroma 向量检索 Top 20
  -> bge-reranker-v2-m3 重排序
  -> 选取 Top 3~5 上下文
  -> 相关性阈值判断
  -> LLM API 流式生成回答与引用编号
  -> 返回答案、引用、调试信息与耗时
```

初始默认参数：

- 分块长度：500 中文字符。
- 分块重叠：80 中文字符。
- 初始召回数量：20。
- 重排序后上下文数量：5。
- 回答引用数量：至少 1 条，最多 5 条。
- 拒答阈值：由评估集校准，MVP 先以 reranker 分数或归一化相关性阈值配置化实现。

### 6.4 回答约束

系统提示词必须包含以下规则：

1. 仅根据提供的上下文回答，不使用上下文以外的事实补全。
2. 关键结论后附上对应引用编号。
3. 上下文没有足够依据时，明确说明“当前知识库未检索到足够依据，无法确认”。
4. 不得伪造文件名、页码、制度条款或引用。
5. 回答采用简洁、可执行的中文；制度类问题优先给出结论、条件和例外。

### 6.5 Agent 编排方案

Agent 框架采用 LangGraph，工具定义使用 LangChain Tools。工作流为：

```text
START -> agent -> tools -> agent -> END
```

Agent 状态至少包含问题、消息历史、工具调用轨迹和引用列表。通过 `recursion_limit` 限制单次任务的最大循环次数；工具只读知识库，不提供删除、修改或外部写操作。未配置 LLM API Key 时，使用同一 LangGraph 图的演示 Agent 节点完成检索工具调用。

## 7. 页面与交互

### 7.1 知识库管理页

- 顶部提供拖拽上传区和“上传文档”按钮。
- 文档表格展示名称、状态、分块数、上传时间和操作入口。
- 每个失败任务可展开查看错误信息，并支持重试。
- 删除与重建索引使用确认弹窗，避免误操作。

### 7.2 智能问答页

- 左侧为会话列表，右侧为消息流和固定输入框。
- 回答生成期间显示流式状态和“正在检索/正在生成”阶段提示。
- 每个回答底部展示引用卡片：文件名、页码、章节、相关原文片段。
- 用户可展开引用原文，以便验证结论；拒答回答需使用明显但克制的提示样式。

### 7.3 检索调试页

- 输入测试问题后，按“初始召回”和“重排序后”两列展示结果。
- 显示候选片段、来源、向量分数、reranker 分数和排名变化。
- 支持复制调试结果，便于记录问题与分析。

### 7.4 评估中心

- 展示评估任务状态和评估集规模。
- 使用指标卡片展示策略 A/B 的 Recall@5、引用命中率和平均耗时。
- 以列表展示失败样例，方便跳转至检索调试页复现。

## 8. 数据设计

| 实体 | 关键字段 | 用途 |
| --- | --- | --- |
| documents | id、name、type、status、source_path、page_count、chunk_count、created_at | 管理原始文档与处理状态 |
| chunks | id、document_id、content、page_number、section_title、chunk_index、content_hash | 保存可检索文本块与来源信息 |
| conversations | id、title、created_at | 组织用户会话 |
| messages | id、conversation_id、role、content、citations、latency_ms、created_at | 保存问答记录与引用 |
| evaluation_cases | id、question、expected_document_id、expected_page、expected_chunk_ids、category | 保存标准测试问题 |
| evaluation_runs | id、strategy、metrics、started_at、completed_at | 保存批量评估结果 |

向量本体存储在 Chroma，业务数据与日志可使用 SQLite；后续可替换为 PostgreSQL，不改变上层 API 契约。

## 9. API 概览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/documents` | 上传文档并创建解析任务 |
| GET | `/api/documents` | 获取文档列表与状态 |
| DELETE | `/api/documents/{id}` | 删除文档及其索引 |
| POST | `/api/documents/{id}/reindex` | 重建单文档索引 |
| POST | `/api/chat/stream` | LangGraph Agent 流式问答，返回答案、引用与工具轨迹事件 |
| POST | `/api/retrieval/debug` | 返回召回、重排与最终上下文结果 |
| GET | `/api/evaluations/cases` | 获取评估问题集 |
| POST | `/api/evaluations/runs` | 启动批量评估 |
| GET | `/api/evaluations/runs/{id}` | 获取评估结果与失败样例 |

LLM 供应商和密钥只能通过环境变量配置，例如 `LLM_BASE_URL`、`LLM_MODEL`、`LLM_API_KEY`；不得写入前端代码、日志或版本库。

## 10. 验收标准

### 10.1 MVP 功能验收

1. 用户可以上传至少 10 个 PDF、DOCX、MD 或 TXT 文档，系统可展示解析成功或失败状态。
2. 成功入库文档的每个 chunk 均可追溯到文件名和页码或章节。
3. 用户提问后，系统可完成“Top 20 向量召回 -> reranker 重排 -> LLM API 回答”的完整链路。
4. 正常回答至少包含 1 条真实引用；展开后可看到与引用一致的原文片段。
5. 对知识库中不存在的信息，系统不会给出确定性虚构结论，而是触发无依据提示。
6. 调试页可以复现同一问题的召回与重排顺序，并展示分数。

### 10.2 评估验收

1. 准备不少于 40 条人工标注问题，覆盖制度查询、流程步骤、条件限制、跨文档对比和无答案问题。
2. 每条有答案的问题标注期望文档及至少一个正确页码或 chunk。
3. 在固定评估集上输出“仅向量检索”与“向量检索 + 重排序”两组指标。
4. 项目报告中说明指标变化、至少 3 个失败案例及相应优化思路。

建议目标值：重排序版本的 Recall@5 不低于仅向量检索版本，引用命中率不低于 80%；该目标需以实际评估集结果为准，不能在简历中虚构数据。

## 12. 风险与应对

| 风险 | 影响 | 应对方式 |
| --- | --- | --- |
| PDF 解析错位或缺页 | 引用不准确 | 保存页码和原始片段；优先使用文本型 PDF；失败任务可重试 |
| 分块边界切断语义 | 召回质量下降 | 使用标题优先分块与 overlap；通过评估集调参 |
| 仅向量检索误召回 | 回答偏题 | 召回 Top 20 后使用 reranker 精排 |
| LLM 脱离上下文回答 | 产生幻觉 | 严格提示词、引用校验和低相关性拒答 |
| API 延迟或失败 | 体验不稳定 | 使用流式响应、超时、重试和清晰错误提示 |
| API Key 泄露 | 安全风险 | 仅后端持有密钥，使用 `.env` 和 `.env.example` 管理 |

## 13. 简历与演示产出

项目完成后应提供：

1. 可运行的前后端项目与 README，说明一键启动、环境变量和示例数据导入方法。
2. 8 至 15 份模拟企业资料，总量约 100 至 300 页，避免使用真实敏感公司资料。
3. 不少于 40 条带标准来源的评估问题集及策略对比报告。
4. 一段 2 至 3 分钟演示：上传资料、提出问题、查看引用、打开检索调试页、展示评估结果。

建议简历描述：

> 构建面向企业制度与技术文档的本地 RAG 问答系统，支持多格式文档解析、页码级引用溯源与无依据拒答。使用 `bge-small-zh-v1.5` 构建 512 维向量索引，并结合 `bge-reranker-v2-m3` 对 Top 20 候选片段精排；通过离线评估集对比 Recall@5、引用命中率与平均响应耗时，持续优化检索质量。

## 14. 后续版本方向

- 混合检索：引入 BM25 与向量检索融合。
- 文档权限：按角色、部门和知识库过滤检索结果。
- 文档对比：自动对比两个版本或多个制度中的差异与冲突。
- 任务路由：将问答、摘要、对比、资料查找分派到不同工具链。
- 线上部署：Docker Compose、对象存储、PostgreSQL 与可观测性日志。
